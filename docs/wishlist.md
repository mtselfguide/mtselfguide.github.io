# 課程許願牆設定說明

訪客可以在網站上直接許願想上的課，也可以對別人的許願按「+1」。
票數越高字越大，我們就照這個順序決定接下來要開什麼課。

- **前端**：`index.html` 的 `#wishlist` 區塊（樣式、版面、腳本都在同一個檔案裡）
- **後端**：`apps-script/wishlist.gs`（Google Apps Script）
- **資料庫**：一份 Google 試算表，兩張工作表（`許願清單`、`投票紀錄`）

```
訪客瀏覽器  ──fetch──►  Apps Script 網頁應用程式  ──►  Google 試算表
           ◄──JSON───                            ◄──
```

全部都在 Google 帳號的免費額度內，**不需要伺服器、不需要付費、沒有第三方服務**。

> **還沒設定完成前，網站完全不受影響。**
> `index.html` 裡的 `WISHLIST_API` 只要是空的，許願牆整區與導覽列連結都維持隱藏，
> 也不會發出任何請求。

---

## 一、部署步驟（約 15 分鐘，只做一次）

### 1. 建立試算表

用協會的 Google 帳號到 <https://sheets.new> 開一份新試算表，
命名為「課程許願牆」之類好認的名字。

> 這份試算表**不需要**（也不應該）設成公開。所有讀寫都經過 Apps Script，
> 訪客碰不到試算表本身。

### 2. 開啟 Apps Script 編輯器

在試算表上方選 **擴充功能 → Apps Script**。

### 3. 貼上後端程式碼

把編輯器裡預設的 `function myFunction() {}` 整段刪掉，
改貼上本專案 `apps-script/wishlist.gs` 的**全部內容**，然後按 💾 儲存。

### 4. 執行 `setup()` 建立工作表

1. 編輯器上方的函式下拉選單選 **`setup`**，按 **執行**。
2. 第一次會跳出授權視窗：**檢閱權限 → 選擇你的 Google 帳號**。
3. 出現「Google 尚未驗證這個應用程式」時，點 **進階 → 前往「專案名稱」（不安全）→ 允許**。
   這是因為指令碼是你自己寫的、沒有上架到 Google 商店，屬正常流程。
4. 回到試算表，應該會多出 `許願清單` 與 `投票紀錄` 兩張工作表。

### 5.（建議）執行 `seed()` 放幾筆起始許願

空空的許願牆沒人想按第一下。函式下拉選單選 **`seed`** 執行一次，
就會塞進 `wishlist.gs` 最上方 `SEED_WISHES` 陣列裡那幾門課（票數從 0 開始）。
想換成別的課名，先改 `SEED_WISHES` 再執行。

### 6. 部署成網頁應用程式

編輯器右上角 **部署 → 新增部署作業**：

| 欄位 | 要選什麼 |
| --- | --- |
| 類型（左側齒輪 ⚙） | **網頁應用程式** |
| 說明 | 隨意，例如「許願牆 v1」 |
| 執行身分 | **我（你的 Google 帳號）** |
| 誰可以存取 | **所有人** |

> ⚠️ 「誰可以存取」一定要選 **所有人**。選「只有我自己」的話，
> 訪客會拿到 401，許願牆只會顯示「讀取失敗」。
>
> 這裡的「所有人」指的是「任何人都能呼叫這支 API」，
> **不是**把試算表公開；訪客只讀得到課程名稱與票數。

按 **部署**，複製畫面上的 **網頁應用程式網址**，格式長這樣：

```
https://script.google.com/macros/s/AKfycb.................../exec
```

> 網址必須以 **`/exec`** 結尾。編輯器裡另一組 `/dev` 結尾的測試網址只有你本人能開，
> 貼上去會讓所有訪客都失敗。

### 7. 把網址填進網站

打開 `index.html`，在檔案底部找到（搜尋 `WISHLIST_API`）：

```js
// ↓↓↓ 只需要改這一行 ↓↓↓
var WISHLIST_API = '';
// ↑↑↑ 只需要改這一行 ↑↑↑
```

把剛才的網址填進去：

```js
var WISHLIST_API = 'https://script.google.com/macros/s/AKfycb.../exec';
```

存檔、commit、push。GitHub Pages 約一分鐘後更新。

### 8. 驗收

打開 <https://mtselfguide.com/>，捲到「課程許願牆」：

1. 看得到剛才 `seed()` 放進去的課名 → **讀取成功**
2. 點一下任一個課名，數字 +1、字變成橘色 → **投票成功**
3. 回試算表看 `許願清單`，該列票數應該同步 +1 → **寫入成功**
4. 在輸入框打一個新課名送出，牆上立刻出現 → **新增成功**

## 二、日常管理

所有管理動作都在試算表上直接改，改完最多 20 秒（快取時間）就會反映到網站。

### 隱藏不想要的許願

在 `許願清單` 把該列的 **狀態** 欄從 `顯示` 改成 `隱藏`。
該筆會從網站上消失，但資料留著（同一個名稱之後也無法被重新許願）。

### 修正課名

直接改 **課程名稱** 欄即可。
若要讓之後的重複判斷跟著更新，**比對用名稱** 欄也一併改成
「去掉空白與標點、英文轉小寫」的版本，例如 `野外急救 WFA` → `野外急救wfa`。

### 合併重複的許願

程式會自動把「攀岩課」「攀岩 課」「攀岩（課）」視為同一門課，
但語意上的同義詞（例如「攀岩」與「岩訓」）還是要人工處理：
把票數加到要保留的那一列，另一列狀態改成 `隱藏`。

### 手動加課、調整票數

`許願清單` 裡直接編輯 **票數** 欄就行。
要手動新增一整列，七個欄位都要填（ID 隨便給一組不重複的英數字即可）。

### 看誰投了什麼

`投票紀錄` 每一列是一次操作：時間、許願 ID、訪客代碼、動作（`add` / `vote`）。
**訪客代碼是瀏覽器隨機產生的亂數，不含任何個人資訊**，只用來擋重複投票。

## 三、可以調整的設定

都在 `apps-script/wishlist.gs` 最上方的「設定區」。
**改完一定要重新部署新版本**（見下一節），否則不會生效。

| 設定 | 預設 | 說明 |
| --- | --- | --- |
| `AUTO_APPROVE` | `true` | 新許願直接上牆。改成 `false` 則先進「待審」，你在試算表把狀態改成 `顯示` 才會出現 |
| `NOTIFY_EMAIL` | `''` | 填入信箱後，每有新許願就寄一封通知信 |
| `MIN_NAME_LEN` / `MAX_NAME_LEN` | `2` / `30` | 課程名稱字數限制 |
| `DAILY_ADD_LIMIT` | `3` | 同一位訪客每天最多許願幾筆 |
| `DAILY_VOTE_LIMIT` | `20` | 同一位訪客每天最多投幾票 |
| `BLOCKED_WORDS` | `[]` | 禁用字詞，例如 `['廣告', '代購']` |
| `CACHE_SECONDS` | `20` | 清單快取秒數，調大可省配額、但資料會更慢更新 |

前端只有一個地方需要動：`index.html` 裡的 `POLL_MS`（預設 `45000`），
決定許願牆多久自動抓一次最新票數。

---

## 四、修改程式碼之後怎麼更新

Apps Script **存檔不等於上線**。改完 `wishlist.gs` 要：

**部署 → 管理部署作業 → 右上角鉛筆 ✏️ → 版本選「新版本」→ 部署**

網址不會變，`index.html` 不用動。

> 如果改了程式卻發現網站行為沒變，九成是漏了這一步。

## 五、配額與流量

Apps Script 免費帳號每天有 **90 分鐘指令碼執行時間**的上限。
為了不浪費，前端已經做了三件事：

1. **捲到許願牆才第一次載入** —— 只看首頁就離開的訪客不會產生任何請求。
2. **離開畫面或切到背景分頁就停止輪詢**。
3. **後端有 20 秒快取** —— 同時間的多位訪客共用同一份結果。

以這個網站目前的流量估算，離上限還很遠。
若哪天真的逼近了，把 `CACHE_SECONDS` 調到 60、`POLL_MS` 調到 120000 即可。

## 六、疑難排解

| 症狀 | 原因與處理 |
| --- | --- |
| 網站上完全看不到許願牆 | `WISHLIST_API` 沒填、或格式不符（必須是 `https://script.google.com/macros/s/…/exec`）。這是設計上的保護：寧可整區不顯示，也不要出現壞掉的區塊 |
| 一直顯示「許願牆讀取失敗」 | ① 部署時「誰可以存取」不是「所有人」 ② 用到 `/dev` 結尾的網址 ③ 改了程式碼但沒建立新版本 |
| 送出後顯示「許願牆還在設定中」 | 忘了執行 `setup()`，或工作表被改名。工作表名稱必須是 `許願清單` 與 `投票紀錄` |
| 按了沒反應、Console 出現 CORS 錯誤 | 前端送出的 `Content-Type` 被改成 `application/json` 了。Apps Script 不回應 CORS 預檢請求，**必須維持 `text/plain;charset=utf-8`** |
| 同一個人可以一直投票 | 他清掉了瀏覽器資料或換了裝置。這是無登入制的先天限制，只能靠每日上限緩解；若真的被灌票，`投票紀錄` 裡看得出是哪個訪客代碼，可以手動扣回票數 |
| 想暫時關掉許願牆 | 把 `index.html` 的 `WISHLIST_API` 改回空字串即可，資料都還在試算表裡 |

想看伺服器端到底發生什麼事：Apps Script 編輯器左側 **執行項目**，
可以看到每一次請求的執行結果與錯誤訊息。

## 七、隱私

- **不收集任何個人資料**：沒有姓名、沒有 Email、沒有 IP。
- 瀏覽器的 `localStorage` 只存兩樣東西：一組隨機訪客代碼、以及你按過哪幾個許願，
  用來避免重複投票。清除瀏覽器資料就會消失。
- 訪客送出的課程名稱一律以純文字顯示（`textContent`），
  不會被當成 HTML 執行，不必擔心有人在輸入框塞程式碼。
- GA4 會另外記錄 `wish_add` / `wish_vote` 兩個事件，詳見 [analytics.md](analytics.md)。
