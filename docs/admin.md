# 報名後台：報名與收費總覽

一頁看完每個場次的報名人數、名額、應收、已收、未收，點開還有名單。
只有協會帳號與指定的幹部看得到，**不會放在公開網站上**。

- **程式**：`apps-script/admin/Code.gs`（主程式）、`apps-script/admin/Overview.html`（總覽頁）
- **寄信**：`apps-script/admin/notify.gs`，說明見 [admin-notify.md](admin-notify.md)
- **新報名通知教練**：`apps-script/admin/coach.gs`，說明見本文「新報名通知負責教練」
- **資料**：一份新的「報名後台」試算表，加上各課程原本的表單回覆試算表（只讀不寫）

```
各課程表單回覆試算表 ──讀取──► 報名後台 Apps Script ──► 總覽網頁（需登入）
                                   │
                                   ▼
                     「報名後台」試算表：活動設定、繳費狀態、寄信紀錄
```

全部在協會的 Google Workspace 帳號內，不需要伺服器、不需要付費。

---

## 一、部署步驟（約 20 分鐘，只做一次）

### 1. 建立「報名後台」試算表

用**協會的 Workspace 帳號**到 <https://sheets.new> 開一份新試算表，命名為「報名後台」。
這個帳號必須能開啟各課程的表單回覆試算表（同一個帳號建立的表單就沒問題）。

### 2. 貼上程式

**擴充功能 → Apps Script**，在編輯器裡：

1. 把預設的 `程式碼.gs` 內容整段換成 `apps-script/admin/Code.gs` 的全部內容。
2. 左側「檔案」旁的 **＋ → 指令碼**，命名 `notify`，貼上 `apps-script/admin/notify.gs`。
   再 **＋ → 指令碼**，命名 `coach`，貼上 `apps-script/admin/coach.gs`。
3. **＋ → HTML**，命名 `Overview`（不要打 .html），貼上 `apps-script/admin/Overview.html`。
4. 按 💾 儲存。

### 3. 執行 `setup()`

函式下拉選單選 **`setup`** → **執行**，第一次會要求授權（檢閱權限 → 選協會帳號 → 允許）。
回到試算表，會多出「活動設定」「繳費狀態」「管理員」三張工作表；重新整理試算表，上方會出現 **協會後台** 選單。

### 4. 設定管理員

在「管理員」工作表的 **Email** 欄（A 欄），一列填一位可以看後台的幹部信箱，「備註」欄可寫名字或職務。
協會帳號本人永遠可以看，不用填。

> 名單刻意不寫在程式碼裡：這個 repo 是公開的，寫進 `Code.gs` 就等於公開所有幹部信箱。
> 之後增減人只要改這張工作表，**不用重新部署**。

### 5. 填「活動設定」

一個梯次一列。各欄的意思：

| 欄位 | 必填 | 說明 | 範例 |
| --- | --- | --- | --- |
| 活動ID | ✔ | 不重複的英數代號，沿用網站的 course_id | `camp-setup-2027-01-09` |
| 活動名稱 | ✔ | 顯示在卡片上 | 野營不慌張 1/9 |
| 活動日期 | ✔ | 日期格或文字皆可，文字要有「年/月/日」才能算倒數 | `2027/1/9` |
| 費用 | ✔ | 每人金額，只填數字 | `1600` |
| 回覆試算表ID | ✔ | 表單回覆試算表的網址或 ID，整段網址貼上即可 | |
| 回覆工作表名稱 | | 留空 = 第一張工作表 | 表單回應 1 |
| 梯次欄 | | 同一份表單有多個梯次時，用哪一題分梯次 | 報名場次 |
| 梯次值 | | 該題答案「包含」這段文字就算這個梯次 | `1/9` |
| 姓名欄 | ✔ | 表單上姓名那一題的**題目全文** | 姓名 |
| Email欄 | | 留空會自動找「電子郵件地址」 | |
| 電話欄 | | 學員填電話的那一題，會放進給教練的新報名通知 | 聯絡電話 |
| 後五碼欄 | | 學員填帳號後五碼的那一題 | 匯款帳號後五碼 |
| 名額 | ✔ | 留空或 0 = 不限 | `8` |
| 行前通知主旨／內文／寄出時間 | | 寄信用，見 admin-notify.md | |
| 狀態 | ✔ | 開放／額滿／結束。「結束」的活動不再同步、不列在總覽 | 開放 |
| 成團人數 | | 報名人數不到就顯示「未達成團人數」 | `6` |
| 報名截止 | | 顯示用 | `2026/12/11` |
| 方案欄 | | 不同方案不同價錢時，用哪一題判斷 | 報名方案 |
| 方案價格 | | `方案名稱=金額`，用 `；` 分隔。答案包含方案名稱就套用；都沒對到就用「費用」 | `過夜=2350；單日=1600` |
| 負責教練Email | | 有新報名時通知誰。可填多位，用逗號或頓號分隔；留空 = 不通知 | `aidan@mtselfguide.com, claire@mtselfguide.com` |

> **題目名稱要一字不差**，包含全形括號與空白。最保險的做法是到回覆試算表第一列直接複製。
>
> **方案價格的順序有意義**：答案同時包含兩個方案名稱時（例如「單日課＋過夜體驗」同時有「單日」和「過夜」），
> 用寫在前面的那個。所以範例把「過夜」放在前面。

### 6. 部署成網頁應用程式

編輯器右上角 **部署 → 新增部署作業**：

| 欄位 | 要選什麼 |
| --- | --- |
| 類型 | **網頁應用程式** |
| 說明 | 報名後台 v1 |
| 執行身分 | **我（協會帳號）** |
| 誰可以存取 | **（你的網域）內的所有使用者** |

> ⚠️ **不要選「所有人」**。名單裡有姓名、Email、帳號後五碼。
> 選「網域內的使用者」再加上「管理員」工作表的白名單，是兩道把關：
> 不是協會網域的帳號根本打不開，網域內但不在白名單的人只會看到「沒有後台權限」。

複製 `…/exec` 結尾的網址，加到瀏覽器書籤。之後也可以從試算表 **協會後台 → 開啟總覽網頁** 打開。

### 7.（選用）每小時自動同步

函式下拉選單選 **`installHourlySync`** 執行一次。
不裝也可以：每次打開總覽頁、或按 **協會後台 → 同步報名資料**，都會先同步。

### 新報名通知負責教練

每次同步（每小時自動、打開總覽頁、按「同步報名資料」）只要某個活動有新報名者，
就寄**一封**信給該活動「負責教練Email」欄的人，內容是這次新報名者的摘要表格：

| # | 報名時間 | 姓名 | 電話 | Email | 方案／梯次 | 帳號後五碼 | 應繳金額 |
| --- | --- | --- | --- | --- | --- | --- | --- |

表格上方另有活動日期、目前報名人數／名額／成團人數；超過名額或剛好達成團會加註提醒。
「方案／梯次」只有該活動有設「方案欄」時才會出現。

- 同一位報名者只通知一次（以「繳費狀態」有沒有這一列判斷）。
- 新加一個活動、第一次同步時，表格會列出當時所有報名者，信上會註明。
- 每封都記在「寄信紀錄」，類型「新報名通知（N 位）」。寄失敗不會自動重寄。
- 想先看長什麼樣子：**協會後台 → 寄一封範例信給自己…**，輸入 `3`，再選活動。
- 主旨、要不要副本給協會信箱，改 `coach.gs` 最上面的 `COACH_SUBJECT`、`COACH_CC`。

> 已經在用的試算表：貼上 `coach.gs`、更新 `Code.gs` 之後，**再執行一次 `setup()`**，
> 「活動設定」最右邊會多出「負責教練Email」欄（既有欄位不會動）。每小時同步的觸發器不用重裝。

### 8. 驗收

1. **協會後台 → 同步報名資料**，視窗顯示「新增 N 位報名者」，且沒有錯誤訊息。
2. 「繳費狀態」裡每個活動的列數，應等於該回覆表（該梯次）的回覆數。
3. 打開總覽網頁，每張卡的「報名人數」與上一步一致，「應收」＝人數 × 費用（或方案價格）。
4. 用一個不在白名單的網域帳號開網址，應看到「沒有後台權限」。

## 二、日常使用

### 「繳費狀態」哪些欄會被同步、哪些不會

| 欄位 | 誰填 | 同步時 |
| --- | --- | --- |
| 活動ID、報名鍵 | 程式 | 新報名者才寫入 |
| 姓名、帳號後五碼 | 程式（從表單） | 學員改了表單回覆就跟著更新 |
| Email | 程式 | 新報名者才寫入 |
| 應繳金額 | 程式先算，管理員可改 | **不覆蓋**（打折、補差額直接改） |
| 已入帳、入帳金額、入帳日期 | 對帳管理員 | **不覆蓋** |
| 入帳通知寄出時間、行前通知寄出時間 | 寄信程式 | **不覆蓋** |
| 備註 | 任何人 | **不覆蓋** |
| 報名狀態 | 管理員（正常／備取／取消） | **不覆蓋**，新報名者預設「正常」 |

報名鍵 = 表單提交時間（ISO 格式）＋「|」＋小寫 Email，用來對應同一筆回覆，**請不要修改**。

### 總覽上的數字怎麼算

- **報名人數**：報名狀態為「正常」的人數。備取、取消另外列出，不算進人數與金額。
- **應收**：「正常」的人的應繳金額加總。
- **已收**：「正常」且勾了「已入帳」的人的入帳金額加總。
- **未收**：應收 − 已收。
- 提醒標籤：**額滿**（人數 ≥ 名額）、**未達成團人數**、**即將開課，尚有人未繳費**（開課前 7 天內，天數可在 `UNPAID_WARN_DAYS` 調整）。

### 有人取消或轉為備取

把該列「報名狀態」改成「取消」或「備取」。表單回覆不用刪，刪了也沒關係，繳費狀態那一列會保留。

### 新增一門課

在「活動設定」加一列，狀態填「開放」。不用改程式、不用重新部署。

### 活動結束後

狀態改成「結束」，就不再同步、也不出現在總覽，資料都還在。

## 三、修改程式碼之後

Apps Script **存檔不等於上線**：**部署 → 管理部署作業 → ✏️ → 版本選「新版本」→ 部署**。網址不變。

改「管理員」名單、「活動設定」不需要這一步。

## 四、疑難排解

| 症狀 | 原因與處理 |
| --- | --- |
| 總覽頁上方出現「這些活動讀不到回覆」 | 訊息會寫是哪一欄找不到。九成是「姓名欄」「梯次欄」等題目名稱跟回覆表第一列不一致，直接從回覆表複製標題貼過來 |
| 「找不到工作表『表單回應 1』」 | 「回覆工作表名稱」打錯，或留空讓它用第一張 |
| 報名人數比實際少 | 「梯次值」對不到答案。梯次值只要是答案的一部分即可，例如答案是「1/9（六）單日課」，梯次值填 `1/9` |
| 應收金額不對 | 檢查「費用」「方案價格」；已經同步進來的人要直接改「應繳金額」，程式不會回頭改 |
| 開網頁顯示「沒有後台權限」 | 信箱不在「管理員」工作表的 A 欄，或拼錯（大小寫沒關係） |
| 開網頁要求登入其他帳號、或顯示無法存取 | 用的是網域外的帳號；部署設定是「網域內的使用者」 |
| 同步顯示「別人正在同步」 | 兩個人同時按，等幾秒再按一次 |
